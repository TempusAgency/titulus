# Titulus launcher card — variant B «Сегменти» — REFERENCE

Еталонні кадри для the launcher card. The original prototype lived in a
temporary directory that was cleaned up on session restart; the source of
truth since then is this file — a set of frames specified by the task that
requested this rebuild, reproduced byte-for-byte by `render.py`.

An earlier revision reshuffled this layout (session id moved into the top
border, counters and model merged, movement indicators split into a segment
that appeared and disappeared only when something was running). That
revision was reverted. The frames below are the corrected layout: **four
segments, always, in this order** — role → id+counters → engine+movement →
place. No segment ever appears or disappears based on runtime state.

`render.py --verify` parses this file and diffs its own output against the
frames below, character-for-character, for state 2 (the one state pinned to
literal text handed down in the task). The rest are generated the same way
and compared too, but only state 2 carries an external byte-exact
requirement.

**RE-RENDERED 2026-09-19 (two point fixes, live card in Claude Code):**

1. **One-cell inset restored, both sides.** A same-day earlier edit had
   removed content_row's leading space entirely, to fix a different bug
   (CC's own outer chrome margin stacking with ours). Once seen live, that
   read as "no padding at all — text glued to the frame" — user asked for
   exactly one blank cell between `│` and the text, symmetric left AND
   right: `│ text …  │`, not `│text…│`. This is a content-layout change,
   not a width change: the card's total outer width is unchanged (the
   inset eats into the space available for text instead of growing the
   box) — see `content_budget()` in `render.py`, which every wrap/truncate
   budget in the file is now derived from.
2. **Double `═` rail removed entirely.** A same-day earlier edit had made
   the rails bordering the `engine` segment go double (`═`) when something
   was busy, as a colour-independent "second signal channel." Once seen
   live, user rejected it outright — the frame is now ALWAYS single-rail
   `─`, in every state, at every width. There is no more "active" concept
   for the frame at all: the `active:` directive is gone from
   `layout.conf`, and the segment_active()/rail_char()/highlight machinery
   is gone from both renderers. Busy is signalled ONLY by the glyph in the
   role/id text (`✻` calm / `✦✶✷✸✹✺` busy) — never by the border.

Concretely: every frame below now starts `│ <glyph|text>` (one leading
space) and ends `…  │` (padded out to a trailing space before the bar), and
every separator/border below is single `─`, even in states 2/3/6 that used
to show `⠹ agents`/`⚙ wf`/busy content. State 2's byte-exact pin (from the
2026-09-19 inset-removal edit) is intentionally broken by this edit; this
file is now the new pin.

Ширина кадрів нижче — 80 колонок (крім стану 6 — 38 колонок).

**Кути (стани 1-6):** верхній лівий і нижній правий кути показані як `/` —
це ЗАМІНА для друку в текстовому документі. Насправді там гліфи TempusGlyphs:
TL = U+E87E, BR = U+E881 (шрифт `~/Library/Fonts/TempusGlyphs-Regular.ttf`).
Рівень зрізу `none` (стан 7) використовує звичайні `┌` і `┘` — без заміни.

## Що не змінюється без прямого прохання (КОНТРАКТ)

Вигляд картки змінювався від ітерації до ітерації кілька разів поспіль — це
дратує власника. Нижче — те, що наступний агент/сесія НЕ повинні
«покращувати» самовільно, без явного прохання власника:

- **Одна одинарна, однотонна рамка.** Завжди `─` (і `│`/`├`/`┤` для
  вертикалей і сепараторів). Ніякого `═`, ніде — ні в рейках між
  сегментами, ні у верхній/нижній грані, ні у вузькому режимі. Немає
  жодного механізму «підсвітки» рамки залежно від активності — це свідомо
  видалено, не забуто.
- **Одна клітинка відступу з обох боків.** Між `│` і текстом — завжди рівно
  один пробіл, і зліва, і справа, симетрично: `│ текст …  │`. Це відступ
  ВСЕРЕДИНІ фіксованої ширини картки (з'їдає бюджет тексту, не розширює
  рамку) — щирина картки від цього не змінюється.
- **Чотири сегменти, завжди, в цьому порядку:** role (роль) → id
  (id-сесії + лічильники) → engine (модель+effort+індикатори руху) → place
  (теки). Жоден сегмент не з'являється і не зникає залежно від стану —
  міняється тільки вміст.
- **Верхня грань — порожня рейка.** Без id, без гліфа — обидва гліфи
  активності живуть у тілі (перед роллю і перед id), не в рамці.
- **Зрізані кути — тільки TL (верхній лівий) і BR (нижній правий).** TR і
  BL завжди звичайні `┐`/`└`. Рівень зрізу `none` (усі чотири кути прямі)
  — окремий явний режим (стан 7), не дефолт.
- **Активність сигналізується ЛИШЕ гліфом у тексті** (`✻` спокій,
  `✦✶✷✸✹✺` рух, одна зміна кадру на секунду) — перед роллю і перед id.
  Ніякого іншого носія сигналу (колір рамки, подвійна рейка) немає.

Якщо щось із цього списку виглядає «застарілим» чи «можна поліпшити» —
питання власнику СПОЧАТУ, зміна файлів ПОТІМ.

## Правила (окрім кадрів)

- **Чотири сегменти, ЗАВЖДИ, в цьому порядку:**
  1. **role** — гліф активності + текст ролі (переноситься, з відступом для
     продовжень).
  2. **id** — гліф активності + id сесії + лічильники (CTX, ліміти 5h/7d,
     eta).
  3. **engine** — модель + effort, і на ТІЙ САМІЙ строці — індикатори руху
     (`⠹ agents ×N`, `⚙ wf ×N`, `⇅ coord`), коли є що показати. Якщо не
     влазить в один рядок — переноситься на кілька рядків того самого
     сегмента (побачити на стані 6), а не ховається чи виноситься окремо.
  4. **place** — теки (по рядку на теку).
- **Жодної появи-зникнення сегмента залежно від стану.** У спокої й під час
  роботи — завжди чотири сегменти; змінюється лише вміст.
- **Верхня і нижня грані — порожні рейки**, без id і без гліфа. Обидва гліфи
  (глиф активності) живуть у тілі: перед роллю (сегмент 1) і перед id
  (сегмент 2).
- **Відступ (2026-09-19, повторний фікс):** між `│` і вмістом — рівно одна
  клітинка пробілу, і зліва, і справа. Симетрично. Ширина картки від цього
  не зростає — відступ забирає місце у тексту, а не розширює рамку
  (`content_budget()` у `render.py` — з нього виводяться всі бюджети
  переносу для role/id/engine/place).
- **Кольори (оновлено 2026-09-19):** рамка/рейки — ОДИН колір всюди, активні
  чи ні: приглушений синювато-сірий `87;104;138`. Раніше активний контур
  фарбувався в терракоту `217;119;87` окремим кольором — прибрано: власник
  подивився живий кадр і не захотів кольорової підсвітки рамки. Термакота
  `217;119;87` лишається зарезервованою під можливий акцент у ТЕКСТІ (не в
  рамці) — зараз ніде не використовується. Було `58;69;92` —
  near-invisible на чорному тлі (контраст ≈2.2:1); збільшено ×1.5 з тим
  самим співвідношенням каналів до контрасту ≈3.7:1. Текст ролі
  `245;246;250` жирний, лічильники `158;162;172`, шлях `124;138;162` — без
  змін.
- **Підсвітки рамки більше немає (2026-09-19, повторний фікс).** Раніше,
  коли щось справді біжило (агенти, воркфлоу, маркер роботи), рейки навколо
  engine ставали подвійними `═`. Власник побачив живий кадр і прямо
  попросив прибрати — «знову з'явились лінії з двома розділювачами». Тепер
  рамка ЗАВЖДИ одинарна, в усіх станах, на всіх ширинах. Єдиний сигнал
  активності — гліф у тексті (`✻`/`✦✶✷✸✹✺`). `active:` більше не існує як
  опція `layout.conf`; `segment_active()`/`rail_char(active)`/`Scene.highlight`
  видалені з `render.py`, той самий механізм видалено з `statusline.sh`.
- «Активний» (для гліфа) = маркер `.working` АБО біжать agents/wf.
  Координаційна пошта сегмент показує, але сама по собі не робить сесію
  «busy».
- Гліф активності: спокій `✻`, рух — анімація кадрами `✦✶✷✸✹✺` (одна зміна
  на секунду в бойовому скрипті); статичні кадри нижче використовують `✹` як
  представника цієї анімації.
- Гілка — `↱` (U+21B1). НЕ `⎇` — його немає в шрифтах стеку, він ламається.
- Роль обрізається на 160 символів.
- Вузька ширина <60: з лічильників лише CTX; шлях переїжджає на власний
  рядок без `↳`; сегмент engine переноситься на кілька рядків, якщо не
  влазить в один.
- `…` для обрізаних шляхів і для обрізаної ролі понад ліміт.

## Гейт ширини

`render.py --audit` прогоняє всі 7 станів × 2 рівні зрізу × ширини
38/60/80/100/120/160 і перевіряє, що КОЖЕН рядок має рівно задану ширину.
Ціль — 0 порушень. Кирилиця, box-drawing та іконки рахуються по 1 клітинці.
