# Titulus launcher card — variant B «Сегменти» — REFERENCE

Еталонні кадри для the launcher card. The original prototype lived in a
temporary directory that was cleaned up on session restart; the source of
truth since then is this file — a set of frames specified by the task that
requested this rebuild, reproduced byte-for-byte by `render.py`.

An earlier revision reshuffled this layout (session id moved into the top
border, counters and model merged, movement indicators split into a segment
that appeared and disappeared only when something was running). That
revision was reverted. The frames below are the corrected layout: **four
segments, always, in this order** — role → id+counters → engine+movement →
place. No segment ever appears or disappears based on runtime state.

`render.py --verify` parses this file and diffs its own output against the
frames below, character-for-character, for state 2 (the one state pinned to
literal text handed down in the task). The rest are generated the same way
and compared too, but only state 2 carries an external byte-exact
requirement.

**RE-RENDERED 2026-09-19** (visual-defect fix, live card in Claude Code):
`content_row()` no longer inserts its own leading space between `│` and the
content — that was OUR inset, on top of whatever margin Claude Code's own
status-line chrome already adds outside this script's output; removing it
was the "start the card at the edge" ask. Concretely: every frame below now
starts `│<glyph|text>` instead of `│ <glyph|text>`. This is a content-layout
change, not a width change — the 80/38-column frame widths below are
unaffected; production width math (COLUMNS-derived, statusline.sh-only) is
a separate, unrelated fix documented in that script's own header. All
budget formulas that assumed the reserved space (`wrap_role`, `wrap_tokens`,
`build_place_lines`) were shifted by 1 accordingly — see render.py. State 2's
old byte-exact pin (from the original task) is intentionally broken by this
edit; this file is now the new pin.

Ширина кадрів нижче — 80 колонок (крім стану 6 — 38 колонок).

**Кути (стани 1-6):** верхній лівий і нижній правий кути показані як `/` —
це ЗАМІНА для друку в текстовому документі. Насправді там гліфи TempusGlyphs:
TL = U+E87E, BR = U+E881 (шрифт `~/Library/Fonts/TempusGlyphs-Regular.ttf`).
Рівень зрізу `none` (стан 7) використовує звичайні `┌` і `┘` — без заміни.

## Правила (окрім кадрів)

- **Чотири сегменти, ЗАВЖДИ, в цьому порядку:**
  1. **role** — гліф активності + текст ролі (переноситься, з відступом для
     продовжень).
  2. **id** — гліф активності + id сесії + лічильники (CTX, ліміти 5h/7d,
     eta).
  3. **engine** — модель + effort, і на ТІЙ САМІЙ строці — індикатори руху
     (`⠹ agents ×N`, `⚙ wf ×N`, `⇅ coord`), коли є що показати. Якщо не
     влазить в один рядок — переноситься на кілька рядків того самого
     сегмента (побачити на стані 6), а не ховається чи виноситься окремо.
  4. **place** — теки (по рядку на теку).
- **Жодної появи-зникнення сегмента залежно від стану.** У спокої й під час
  роботи — завжди чотири сегменти; змінюється лише вміст.
- **Верхня і нижня грані — порожні рейки**, без id і без гліфа. Обидва гліфи
  (глиф активності) живуть у тілі: перед роллю (сегмент 1) і перед id
  (сегмент 2).
- **Кольори (оновлено 2026-09-19):** рамка/рейки — ОДИН колір всюди, активні
  чи ні: приглушений синювато-сірий `87;104;138`. Раніше активний контур
  фарбувався в терракоту `217;119;87` окремим кольором — прибрано: власник
  подивився живий кадр і не захотів кольорової підсвітки рамки (у вузькому
  стані 6, де сегмент engine переноситься на 2 рядки, вона виглядала як «дві
  помаранчеві смуги»). Термакота `217;119;87` лишається зарезервованою під
  можливий акцент у ТЕКСТІ (не в рамці) — зараз ніде не використовується.
  Було `58;69;92` — near-invisible на чорному тлі (контраст ≈2.2:1);
  збільшено ×1.5 з тим самим співвідношенням каналів до контрасту ≈3.7:1.
  Текст ролі `245;246;250` жирний, лічильники `158;162;172`, шлях
  `124;138;162` — без змін.
- **Підсвітка:** коли щось справді біжить (агенти, воркфлоу, маркер роботи),
  рейки, спільні з engine (між id/engine і між engine/place), стають
  подвійними `═` замість одинарних `─` — це ЄДИНИЙ сигнал підсвітки тепер
  (кольору більше немає, тільки подвійна лінія). Рейка між role/id і
  зовнішні верхня/нижня грані завжди одинарні — вони не межують із engine.
  Цей подвійний рядок — уже й був «другим каналом сигналу поза кольором»
  (мав працювати при `NO_COLOR=1`), просто раніше він дублював кольорову
  підсвітку, тепер він єдиний. ВІДКРИТЕ ПИТАННЯ: коли вузька ширина розбиває
  engine на 2 рядки (стан 6), подвійна рейка над і під сегментом без
  кольору може так само читатись як «дві риски» — власник це ще не
  оцінював, рішення за ним.
- «Активний» (для підсвітки) = маркер `.working` АБО біжать agents/wf.
  Координаційна пошта сегмент показує, але сама по собі НЕ підсвічує.
- Гліф активності: спокій `✻`, рух — анімація кадрами `✦✶✷✸✹✺` (одна зміна
  на секунду в бойовому скрипті); статичні кадри нижче використовують `✹` як
  представника цієї анімації.
- Гілка — `↱` (U+21B1). НЕ `⎇` — його немає в шрифтах стеку, він ламається.
- Роль обрізається на 160 символів.
- Вузька ширина <60: з лічильників лише CTX; шлях переїжджає на власний
  рядок без `↳`; сегмент engine переноситься на кілька рядків, якщо не
  влазить в один.
- `…` для обрізаних шляхів і для обрізаної ролі понад ліміт.

## Гейт ширини

`render.py --audit` прогоняє всі 7 станів × 2 рівні зрізу × ширини
38/60/80/100/120/160 і перевіряє, що КОЖЕН рядок має рівно задану ширину.
Ціль — 0 порушень. Кирилиця, box-drawing та іконки рахуються по 1 клітинці.
